# Cutting a release

A release of this repository is a Zenodo record with a DOI, made so that the
manuscript can cite the exact code and numbers it reports. The point is that
someone who downloads the archive can run `make paper` and get the tables the
paper quotes. Everything below exists to make that true.

## What has to hold before a tag

The first four are checked by `make check`, which is what CI runs, so the
honest version of this list is: `make paper && make check` passes on a clean
checkout, and then the rest.

1. **The versions agree.** `scripts/check_consistency.py` compares
   `pyproject.toml` against `src/organgrow/__init__.py`, `CLOSED_MODEL.md`,
   `PAPER_NUMBERS.md`, `CITATION.cff`, and `manuscript/PAPER.md` and
   `manuscript/MANUSCRIPT.md` where the checkout carries them.
   A release that disagrees with itself about its own version is not citable.
2. **The stamp is real.** `PAPER_NUMBERS.md` names the commit that produced
   its numbers, that commit is in the history of HEAD, and the tree carried no
   uncommitted changes when it was written. The dirty check covers the whole
   tree apart from what the run writes itself, because the Makefile decides
   which Python runs and the first version of this check did not watch it.
   Getting a clean stamp takes two commits: commit the code, then run
   `make paper` and commit the regenerated numbers.
3. **The manuscript matches the results.** `scripts/29_check_manuscript.py`
   recomputes every model number from the result files, formats it as the
   manuscript writes it, and requires that string to be present.
4. **The tests pass and the lint is clean**: `make test` and pyflakes over
   `src scripts figures tests`.
5. **The caches are honest.** Scripts that cache simulations carry a
   fingerprint of the parameters and of the engine (`organgrow.runcache`). Cut
   a release from a run made *without* `OGROW_ADOPT_CACHE`, so that every
   cached file on which the numbers rest was produced by the code being
   released.
6. **`CITATION.cff` is current**: the version matches, `date-released` is the
   day of the tag, and the author list, affiliations and ORCID identifiers are
   the ones going on the paper.

## Doing it

```bash
make paper && make check          # no OGROW_ADOPT_CACHE
git add -A && git commit -m "release vX.Y.Z"
git tag -a vX.Y.Z -m "vX.Y.Z"
git push && git push --tags
```

With the GitHub–Zenodo integration switched on for the repository, pushing the
tag creates the record and mints the DOI. Then:

- put the concept DOI, the one that always resolves to the newest version,
  into `README.md` as a badge and into the manuscript's data availability
  section;
- put the version DOI, the one that resolves to this release alone, into the
  manuscript where it says which code produced the numbers.

## What is deliberately not in the archive

`manuscript/` is versioned in the repository and marked `export-ignore` in
`.gitattributes`, so the archive a tag produces, which is the one Zenodo
stores, does not carry the draft, its ledger or the notes to the authors. To
see exactly what a release will contain before tagging:

    git archive --format=tar HEAD | tar -t | less

In that archive `make check` reports the manuscript as absent and the stamp as
uncheckable against a history, and checks everything else.

`results/` and `figures/out/` are regenerated by `make paper` and are not
committed, so the archive is the recipe rather than the dish. `source_data/`
is committed, because it is what a reader checks a figure against without
rerunning anything. The transcriptome tables under `data/` are committed for
the same reason; the raw GEO files are not, and the script says which
accession to put where to redo them.

## Before the first release

- ORCID identifiers for all seven authors are missing from `CITATION.cff`.
- `pandoc` is not installed on the machine the numbers are generated on, so
  `make paper` cannot build the Word file and skips it. The manuscript is
  `manuscript/MANUSCRIPT.md` either way, but the coauthors' copy with the notes needs it:
  `brew install pandoc`.
- Reference [11] in the manuscript needs its page range, and [10] needs a
  volume if one has been assigned since it appeared online.
- The three figures the manuscript does not use are listed in `manuscript/FIGURES.md` as
  supplementary; decide whether they travel with the record.
